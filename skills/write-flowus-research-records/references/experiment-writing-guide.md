# 实验报告的清楚表达指引

默认使用用户已经认可的中文研究笔记写法：把事情讲明白，再保留必要的技术细节。不要把实验报告写成只有模型自己看得懂的术语清单。以下要求用于新写、补全和重写实验正文；局部修改只补足相关上下文，不借此重写未获授权的内容。

## 正文与 Agent 细节分开展示

用户填写的“实验内容”面向人阅读，简洁说明做了哪些实验即可。保留用户这种写法，不用完整的执行参数和核验过程把它扩成长篇。

“本次评估设置”等供 agent 执行、复现或核查的资料，放进默认收起的 FlowUs 原生折叠列表。模型和路径、种子和并行数、精确采样范围、时间窗口、硬件及任务核验记录等保存在折叠子块中，折叠标题简短说明用途并按主文件要求添加 `✦`。折叠标题写入 `toggle.rich_text`，详细段落放在独立子块中；回读父块和子块，确认详细内容确实被收在折叠里。

按是否帮助人理解当前结果决定正文保留什么。比较对象、必要的控制条件、指标含义和会影响结论的异常或限制，仍在对应图文附近简要交代；只有复现时才需要的细节留在折叠里，不在正文、图注和折叠之间反复重复。

## 1. 先说清在比较什么

开头让读者知道这次改了什么、为什么这样比较，以及准备用什么判断好坏。例如比较输入处理方式，就先说明输入从哪里来、经过哪种处理、交给哪个网络，再列出各组设置。

关键概念在首次使用时就地解释。说明它是什么、起什么作用、在本次实验里怎样用；不能只给缩写或英文全称。只解释影响当前理解的概念，不为凑“入门教程”扩写无关知识。

简要交代影响比较的条件，例如改了什么、是否使用同一份模型、重复测试是否足够支持当前判断。完整参数、逐项次数推算和执行安排放在 agent 折叠列表中；只有理解图表所必需的次数或差异才在图文附近保留。出现多项差异时据实说明，不能擅自把比较写成只有一个变量不同。

## 2. 把术语接到具体操作上

优先写“谁做了什么，结果怎样”。专业词确实有用时，先解释它对应的操作，再使用这个名称。不要把多个名词压成一句话，让读者自己猜它们的关系。

下面仅是表达方式示例，不是给任何实验预设事实或结论；也不是禁用词表。

| 不要直接丢给读者的说法 | 先解释成读者能跟上的话 |
| --- | --- |
| 首次达标的中位检查点 | 每组训练三次，把第一次通过检查的更新次数从小到大排好，取中间那次。 |
| 冻结策略复测 | 停止训练，保持这份模型的参数不变，再跑一遍相同测试。 |
| 配对随机种子 | 各组使用相同的随机起点编号；如果已核对初始权重相同，就具体说明这一点。 |
| 成功样本条件均值 | 这里只选择通过测试的结果，再计算它们的平均误差。 |
| 结论的适用边界 | 这次测了哪些情况，还有哪些情况没有验证。 |

像“学会了”“收敛了”“通过了”这样的词也要说清口径：这次怎样算通过、在哪些保存下来的模型上检查、训练结束后又测了什么。第一次通过某个检查和以后每次都能通过，需要分别看证据。

数字例子确实能帮助理解时再用；自行构造的例子必须标明不是实测数据。正文保留解释结果所需的关键数值，其余精确数值放在图中或本地记录里。

## 3. 带着读者看图

每组结果围绕它要回答的问题来讲，不机械套同一组小标题：

- 图前先告诉读者为什么看这张图、应该比较什么。
- 首次出现的指标说明它衡量什么、单位是什么、越大还是越小更好。不同指标即使都叫“误差”，计算或统计对象不同也要说清。
- 解释横轴、纵轴、颜色和线条分别是什么；画了平均线、阴影或散点时，说清它们代表哪些训练或测试结果。
- 接着描述真正看到的现象：整体接近、前期略快、通过次数更多，或某些条件下卡住。再说明这些观察怎样回答前面的问题。
- 保存点之间没有检查时，只说“在这次检查时第一次发现通过”，不能把图上的点当成精确的收敛起点。
- 只统计部分成功样本、重复测试出现不同结果、各组条件不完全相同时，就近解释这些情况怎样影响读图。

一次读图说明已经够用时不重复长篇图注。图注交代来源、条件和必要的统计方式，正文负责解释现象与意义。自己生成的实验图使用中文；模型名、符号和必要缩写保留到能准确识别即可。

插图后还要在 FlowUs 页面的正常阅读视图中，比较图内文字和正文的实际显示字号，不能只看本地大图。图内文字明显偏小就等比例放大图片块的页面显示尺寸，再检查标题、坐标轴、图例和标注是否无需点开原图也能看清。保持图片纵横比和内容完整；只增加文件像素而页面显示大小不变，不算解决。无法查看实际页面或调整显示尺寸时，按主文件要求如实说明未完成项。

## 4. 结论直接，但跟着证据走

先回答实验问题：哪组在什么条件下更好，还是目前整体接近、看不出稳定的优势。然后说明依据和会改变判断的例外，不用一串抽象限定词代替解释。

训练曲线接近与实际测试结果相同，是不同判断；一次测试全通过与重复运行都能通过，也需要不同证据。没有发现某种方式稳定更好，不等于已经证明几种方式没有区别。

结果有波动就直接写发生了什么，例如“同一份模型第一次通过，重跑却卡住”。原因没有查清时，说明尚不清楚；不能自动归因于随机种子、仿真后端或某项算法改动。

可以使用“就这次测试看”“在这些条件下”等自然限定。不要为贴近用户口吻而强行赞同猜测、放大提升、编造感受，或把一组结果推广到未验证的场景。

## 5. 交付前按人的读法检查

连续读一遍，确认读者能回答：这次在比什么？为什么这样比？术语对应什么操作？图中哪些现象支持结论？哪些反例还需要保留？

如果某句话只有专业名词、没有具体对象和动作，就补上解释或换成普通说法。只供 agent 复现或核验的深层参数和实现细节放进折叠子块，正文保留人理解结论所需的信息。不要用固定字数、段落数或例句代替这次判断。

审阅时保持 agent 详细设置的折叠列表收起，确认人读正文仍能看懂实验和结论；再展开核对详细记录。逐张检查页面中的图文比例，确保图片上的文字清楚可读，偏小的图片已经等比例放大。

沿用原实验记录的栏目，保留用户原文、时间和未要求修改的内容。语言重写不改变实验事实；下一步计划仍以用户提供的内容为准。写入 FlowUs 时继续执行主文件中的 AI 标记、原生图表和回读要求。
