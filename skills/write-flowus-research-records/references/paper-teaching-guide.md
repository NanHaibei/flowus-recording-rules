# 教学型论文笔记写作指引

本指引用于论文正文的新增、补全和重写，与主文件中的证据、人工内容保护和 FlowUs 排版要求一起执行。默认读者第一次接触论文方向，目标是让其理解问题如何引出方法、方法如何产生结果，以及实验能够证明什么。用户指定的深度、形式与修改范围优先。

## 1. 建立读者能够跟随的主线

- 先明确任务、可获得的输入、希望得到的输出和实际困难。选择一个容易想象的场景，让后文的新模块都有要解决的问题。
- 从“现有办法在这里为什么不够”推导新设计。相关工作服务于这个推导，避免按论文名称依次罗列而缺少问题之间的联系。
- 将整体图景、核心步骤、进阶细节分层。先解释一条完整的数据流，再进入模型结构、损失、证明或超参数；必要的前置知识在首次使用处补齐。
- 保留理解方法所需的技术细节，按复杂度调整篇幅，不设固定字数、段落数或公式数量。较简单的论文可以简明，复杂方法需要足够铺垫。
- 局部更新时，先读前后文，使新增段落能接入已有主线。只补全理解该部分所需的内容，不借此改写未授权部分。

## 2. 让概念与模块在出现时就能被理解

首次实质使用一个重要概念时，解释它是什么、用于解决什么问题、在本文中承担什么职责。解释深度取决于它对理解的影响：读者只需知道某个工具的作用时，先给准确的直觉；理解贡献必须掌握其机制时，再继续展开。

缩写的全称只能帮助识别名称。例如，写出 AWR 是 advantage weighted regression 以后，还应说明“它利用动作相对于状态基准的好坏程度，调整模仿各次尝试的力度”。公式与实现细节随后接上这层直觉。

对每个核心模块，讲清楚它接收什么、处理什么、为什么这样处理、输出什么、交给哪个后续环节。把这些信息写成相互承接的段落，避免每节都机械重复同一组小标题。

多阶段系统要说明各阶段的数据来源、训练目标、更新或冻结的部分，以及推理时实际运行的模块。论文没有训练或部署阶段时，按其真实结构讲解，不套用机器学习流程。

遇到同名但含义不同的概念，应在读者可能混淆的位置说明。例如，多层控制中“动作”可能分别指整条参考与当前关节目标，生成模型的内部时间可能不同于物理执行时间。类似区别也可能出现在坐标系、损失与评价指标、训练真值与部署观测之间。

## 3. 用例子连接模块

选择与论文任务和证据相符的具体例子，沿输入、处理、输出及反馈走过完整过程。在关键模块处回到同一个例子，说明当前步骤补上了什么能力，最后能让读者把分散章节重新串起来。

例子可以来自论文的真实实验，也可以是用于解释方法的构造场景。两者需要明确区分：构造场景不得写成实际观察到的逐帧过程，也不能为论文补出没有验证的能力。

复杂权重、优化或概率过程在数字例子能明显减少理解负担时，可使用简单数值演算。明确说明数值仅用于教学，不是论文实验结果或实际超参数；同时检查计算正确、假设清楚。易于直接理解的内容不必额外制造数字例子。

## 4. 公式的讲解顺序

公式出现前，说明当前问题与引入这个量的目的。随后定义变量、下标、单位和取值范围中对理解必要的部分，解释主要运算的含义，再说明公式如何用于训练、推理或评价。

给出读者可以用语言复述的直觉，例如“这个量衡量本次尝试比该状态通常表现好多少”。若需要进一步理解，再逐项展开运算或补一个数值例子。不能让公式成为一段没有解释的名称替换。

涉及推导时，交代关键步骤成立所需的假设及其作用。把理解核心方法必须掌握的部分放在主线中，将较深的证明、数值求解或实现细节后置，保证读者读到公式前已知道它为什么有用。

区分论文原式、为教学补充的等价写法与独立构造的例子。若为避免符号冲突而改名，说明与原文的对应关系。不得猜测未公开的变量分解、权重或实现细节。

## 5. 让实验回答前面的问题

每组实验按以下信息组织，组织方式可随图表调整：

1. 要验证哪个主张、模块或设计理由，为什么这个比较可以提供证据。
2. 数据、任务、训练和测试范围；比较对象改变了什么，哪些条件相同或不同。
3. 指标测量什么、单位是什么、越高还是越低更好。区分绝对成功率、相对性能比例、百分点和相对百分比。
4. 图的坐标轴、图例、曲线或子图怎样对应实验；表的行列和主要分组怎样读。先帮助读者找到应比较的对象，再解释差异。
5. 主要观察与它支持的结论；同时保留影响判断的例外、比较条件及不确定性。定性演示、重复采样统计、仿真与真机属于不同证据，不能混用。

图前提供阅读方向，图后解释观察如何回应方法设计。原始 caption 的中文翻译保持忠实，自己的背景解释与分析放在正文，不能改写图注来增补论文没有的主张。

消融实验要说明去掉或替换了什么，以及比较能隔离什么因素。存在多项差异时，限制归因范围。置信区间用于表达估计不确定性，不自动证明任何细小差异都显著；按照原文能支持的程度解释。

## 6. 用户认可笔记的简短正例

以下片段提炼自用户认可的《Generate, Track, Improve: Perceptive Multi-Skill Humanoid Locomotion with RL-Fine-Tuned Motion Generators》教学版，用于示范组织方式。后续论文应使用自己的任务、概念和证据。片段中的 ✦ 示范实际笔记的 AI 标记；写入 FlowUs 时仍须按主文件使用原生图片、图注和公式。

### 从概念走到分层关系

> 参考动作描述希望机器人怎样运动。把各时刻的目标排起来，就得到参考轨迹；但机器人受到推力或发生打滑时，仍需要控制器持续纠正。✦
>
> 动作跟踪器观察当前状态，比较参考目标，再输出关节控制目标。生成器则决定接下来应该给出哪一段参考。因此，上层负责选择短时运动，低层负责当前时刻的执行；接近箱体时，两层需要共同完成提前减速、起跳与落稳。✦

这段先解释参考为什么不等于执行结果，再引出 tracker 的必要性，最后说明 generator 与 tracker 的分工，使下一节讨论数据与训练有明确对象。

### 从评价直觉走到 AWR 权重

> 困难地形上的一次进步，原始得分可能仍低于简单平地上的普通动作。优势用本次回报减去该状态的价值基准，衡量这次选择比通常表现好多少；AWR 再让正优势样本获得更大学习权重。✦
>
> 用一个纯数学示例理解权重，以下数值不是论文实验结果或真实超参数。若两次归一化优势分别为 1 和 −1，温度系数取 1，权重上限至少为 3，那么指数权重约为 2.72 和 0.37。两份轨迹都能参加学习，但前者的误差权重约为后者的 7.4 倍。✦

实际笔记还应在相应位置展示权重公式，定义温度系数、截断上限与归一化方式，并说明该权重怎样进入生成器的训练损失。数字例子帮助理解已有机制，不替代公式和来源核查。

### 把实验连接到设计理由

> 这组对照要检查，改善是否只来自重新收集新地形数据。Plain BC 将采到的参考同等模仿，AWR 则依据优势分配学习权重。Plain BC 表现较差，支持需要区分尝试质量；这个结果不能直接推广为行为克隆在所有任务中都无效。✦

这段明确比较目的、关键区别与结论边界。实际笔记还须交代对应实验设置、指标和图表读法，使读者能够自己核对该结论。

## 7. 交付前的教学审阅

从初学者视角连续读一遍，检查以下理解结果：

- 能说清任务与动机，知道每个主要设计为什么被引入。
- 沿输入输出能复述方法，知道训练材料、模块与阶段如何连接。
- 重要概念在必要位置已解释，关键公式的变量、目的和作用能用语言复述。
- 具体例子能走过完整过程，构造的场景与数值不会被误认成实验事实。
- 能读懂主要图表，判断结果支持哪个主张，以及有哪些适用边界。
- 困难内容已有必要铺垫，进阶细节没有阻断核心理解；技术细节与证据仍完整准确。

发现关键概念跳跃或推理断层时，补齐前置说明并调整相邻段落，再核对相关公式、案例与实验是否仍然一致。教学审阅与来源核验、媒体检查、格式回读共同决定笔记是否完成。
