# Write FlowUs Research Records

在 FlowUs 中编写可核查、易阅读的科研记录。先判断任务属于“论文笔记”还是“实验报告”，执行共同规范后进入对应工作流；混合任务分别处理，不得把一个页面的内容写入另一个页面。

## 任务路由

- 新增论文、补全论文信息、完善论文阅读笔记或检查重复论文：执行“论文笔记工作流”。
- 完成或修改一份实验报告、插入实验结果、补充结论或标记报告完成：执行“实验报告工作流”。
- 仅查询或总结现有页面：遵守读取范围和证据要求，不执行未获授权的写入。

## 共同执行规范

### 1. 连接和定位

- 优先使用 FlowUs 官方 `$flowus-cli` Skill；仅支持 MCP 或用户不希望安装本地程序时使用 FlowUs MCP。
- 第一次连接、认证失败或不清楚接口能力时，完整阅读 [FlowUs 连接与原生功能](references/flowus.md)。
- 写入前运行 `flowus --json whoami`，确认身份、工作区和权限。无法可靠写入时只提供草稿，并明确说明尚未写入。
- 使用页面 ID、数据库 ID、规范化标题或链接确定唯一目标。目标存在歧义时先请用户确认。
- 读取目标的实际字段、选项和内容结构；保留现有字段名称和类型，不擅自修改数据库结构或属性选项。
- 将后续读取、上传、插入、更新和回读限制在已确认的目标页面、数据库及其子块内。

### 2. 证据和写作

- 只把论文原文、用户提供的事实、实验数据或已核验来源支持的信息写成事实；不得编造设置、指标、结果或原因。
- 清楚区分原文结论、直接观测结果和自己的分析或推断。证据不足或材料冲突时明确说明，不用常识补全。
- 以读者能够理解为目标，先交代问题和上下文，再解释过程、证据和结论；使用简洁、准确的标题和段落。
- 保留目标页面中未被要求修改的文字、顺序、格式、附件和属性。只修改完成当前任务所必需的内容。
- 不夸大结果，不把相关性写成因果，不把尚未执行的工作写成结果。

### 3. 学习近期笔记的人工文风

每次在 FlowUs 生成或改写内容前执行以下步骤：

1. 读取目标所在数据库、分类或实验报告目录中最近更新的 3–5 篇同类笔记；目标页面已有的用户内容也可作为样本。
2. 将没有 `✦` 的内容作为人工内容候选，优先选择实验原因、原始实验内容、个人总结、手写批注等能够确认由用户填写的段落。旧笔记没有标识且来源不明时，不得仅凭“没有 `✦`”断定为人工内容。
3. 在内部提炼文风和格式特征，包括标题层级、章节顺序、段落长度、句式节奏、第一或第三人称、术语中英文习惯、列表密度、强调方式、图注写法、表格布局和结论语气；不要把这份风格分析写入目标页面。
4. 使用提炼出的风格组织新内容，使其与用户近期笔记自然一致。只学习表达和排版，不复制原句、事实、结论或错误。
5. 样本不足时扩大到同一数据库中更早的相关笔记；仍没有可靠人工样本时，保持目标页面现有格式并使用简洁、克制的技术写作风格。
6. 文风模仿不得覆盖准确性、证据、任务结构和用户明确要求。

### 4. 标记 AI 生成内容

- 统一使用 `✦` 表示 AI 生成或 AI 改写的文字。
- 凡由 AI 新写、扩写、翻译、概括、重组或实质性改写的可见文字块，都在该块最后一个字符后直接添加 `✦`。适用范围包括正文段落、标题、列表项、引用或提示块、图注、表注、说明文字、分析和结论。例如：`该方法使用历史观测提高运动跟踪稳定性。✦`
- 一个文字块同时包含用户原文和 AI 补写内容时，将整个文字块视为 AI 生成并在末尾添加 `✦`。仅原样移动、复制或保留用户文字时不要添加。
- 逐字引用的论文原文、论文标题、作者、链接等来源元数据，以及未经改写的用户原文不属于 AI 生成内容；AI 翻译、释义或改写后必须添加 `✦`。
- AI 创建或整理的简单表格不逐单元格添加标识；在表格紧邻下一行插入一个仅包含 `✦` 的普通段落。表格下方另有 AI 生成的说明时，该说明段落仍需在末尾添加 `✦`。
- 不要把 `✦` 写入纯公式表达式、URL、数值单元格或图片本体；对应的 AI 解释文字和图注仍按规则标记。
- 只标记本次新生成或实质性改写的内容，不追溯修改本次任务未触及的旧内容。

### 5. 图片、表格和公式

- 将图片、实验截图和生成图表先保存为本地文件，再通过 FlowUs 文件接口上传；页面中的图片本体只能使用上传后的 FlowUs 文件或图片块，禁止使用外链图片。
- 使用来源中的原图时保留完整 caption 和必要来源说明。将图、表和公式放在对应解释附近，不集中堆放在独立附录。
- 只有来源没有合适图片且整理图确有帮助时才自行生成，并明确标注“根据来源数据整理”。不得伪造或重绘实验结果。
- 表格形式由具体工作流决定：论文原有实验表格使用截图；实验报告的数据表使用 FlowUs 原生表格。
- 块级公式使用 FlowUs 原生公式块，行内公式使用公式富文本；不得以普通文本、Markdown、行内代码或代码块显示 LaTeX 源码。
- 所有上标 `^`、下标 `_` 及同类分组运算符的操作数都必须使用花括号，包括单字符。使用 `x_{t}`、`q^{*}`、`L_{total}`、`a_{t-1}^{(k)}`，禁止 `x_t`、`q^*`、`L_total` 或 `a_t^{(k)}`。
- 原生上传、表格或公式能力不可用时，不得降级为外链或模拟内容；明确报告对应部分尚未完成。

### 6. 写入和回读

1. 在写入前记录目标页面或数据库 ID，并保存必要的原始属性和内容结构。
2. 先上传媒体，再按最终阅读顺序写入属性、正文和原生内容块。
3. 写入后重新读取同一目标，核对页面 ID、属性、标题层级、正文、图注、表格、公式和媒体。
4. 逐块检查本次 AI 生成或实质性改写的文字都以 `✦` 结尾，AI 创建的简单表格下方存在独立 `✦` 段落，且未修改的人工内容没有被误标。
5. 检查页面不存在外链图片、可见 LaTeX 源码或没有花括号的上下标。
6. 只有所有必需步骤均已成功并经过回读验证，才向用户报告完成；返回页面链接或明确的记录 ID，并列出未完成项。

## 论文笔记工作流

### 1. 获取原文并查重

1. 优先获取作者发布的 PDF、arXiv 或正式出版版本，阅读全文中与背景、方法、实验和限制有关的部分，不只依赖摘要。
2. 写入前按 arXiv ID、DOI、规范化标题和论文链接检查重复记录。除非用户明确要求，否则更新已有记录，不创建重复记录。
3. 确认目标论文数据库及其属性结构。

### 2. 确认分类和元数据

- 用户已指定分类时使用该分类；若它与数据库现有分类不一致，说明差异并请用户确认。
- 用户未指定分类时，先读取数据库现有选项，根据主要研究问题、核心方法和应用场景推荐一个分类；确有歧义时最多给出两个备选。获得明确确认前可以准备草稿，但不得写入或自行新增分类。
- 核验标题、作者、发表信息和链接。作者单位优先记录第一作者单位；无法核实时标记未知，不得猜测。
- 优先记录 arXiv 链接；没有 arXiv 时使用正式出版页、项目主页或其他可靠来源。
- 新建记录时，将 `阅读状态` 设置为数据库现有的“未阅读”或未读等价选项，例如 `😲待阅读`；不得因为已生成笔记而设置为“粗读”或“精读”。更新已有记录时保留原状态，除非用户明确要求修改。

### 3. 编写学习笔记

正文不重复数据库元数据，直接从以下结构开始，并按论文内容增加子标题：

#### 1. 问题背景

说明所属领域、具体任务、重要性，以及理解论文所需的背景知识。

#### 2. 现有工作的问题与论文动机

解释已有方法的限制、论文要解决的核心矛盾和提出新方法的原因；区分作者明确陈述与自己的理解。

#### 3. 论文方法

按由浅入深的顺序解释：

1. 前置知识、术语与符号
2. 方法整体直觉
3. 输入、输出和数据流
4. 分阶段训练或推理流程
5. 各模块的作用、设计理由和前后衔接
6. 关键公式、变量、输入输出和优化目标
7. 与现有方法的差异
8. 一个具体示例或端到端过程

论文提供的方法总览图、系统架构图、流程图、模块图、算法示意图及其他有助于理解数据流的图片必须全部收录，并放在相应解释附近。不得只用文字概括，也不得用自行绘制的示意图替代论文原图。

#### 4. 实验结果

- 说明实验设置、比较对象、指标、主要结果及结果能够支持的结论。
- 收录论文中所有与实验结论相关的曲线图、柱状图、对比图、消融图、定性可视化、趋势图和机器人或场景展示图，并放在对应说明附近。
- 需要收录的论文实验表格必须以截图插入，截图同时包含完整表头和论文 caption；不得重建、转录为 FlowUs 原生表格或使用其他形式模拟。

#### 5. 方法缺陷与未来工作

分别记录作者承认的限制、从实验条件可以直接判断的适用边界和作者提出的未来工作；将自己的内容标注为“分析”或“推断”。

### 4. 论文笔记完成检查

- 已完成查重、分类确认和元数据核验。
- 新记录的阅读状态为未读等价选项，已有记录保留原状态。
- 第一段标题是“1. 问题背景”，且方法、实验、限制章节完整。
- 方法数据流、模块衔接、公式语境和端到端过程解释清楚。
- 论文已有的相关方法图和实验图均已收录，图注完整。
- 实验表格以带完整表头和 caption 的原表截图收录。
- 已按共同规范完成图片、公式和回读检查。

## 实验报告工作流

### 1. 锁定页面并检查前置条件

1. 要求用户使用页面链接、页面 ID 或其他唯一标识指定一份实验报告；目标不唯一时不得写入。
2. 读取并记录不可变页面 ID。禁止创建、修改或删除其他报告、页面、数据库记录、模板或数据库结构。
3. 确认以下内容已经由用户填写在目标报告中：实验开始时间、实验原因、实验内容。任一项为空、只有占位文字或无法确认来源时，停止写入并列出缺失项；不得代填或猜测。
4. 下一步计划不属于前置条件。用户未提供时保留为空或保留原文。

### 2. 编写实验内容和结论

- 依据目标报告、实验记录、用户说明、附件和实验数据，精炼“实验内容”。只记录做了什么、关键设置和直接结果，不混入实验原因、背景、评价、结论或下一步计划。
- 依据可核查材料编写“实验结论”，简洁说明主要结果、与预期或对照的差异，以及证据明确显示的限制或异常。
- 材料之间冲突、指标定义不清或证据不足时，保留无法确认的内容并向用户说明，不覆盖为确定结论。
- 用户提供实验结果图片时上传原图；需要根据数据生成图表时只使用实际数据，并在图注中注明指标、对照和必要的处理方式。
- 实验数据需要表格呈现时，使用 FlowUs 原生表格，只保留直接相关的列和数据；回读确认表头、行列和数值未错位。

### 3. 完成时间、标题和下一步计划

正文、媒体、表格和公式写入并回读成功后：

1. 使用 FlowUs 原生【日期】属性，在用户填写的开始时间后补充实际完成时间，优先设置为包含开始与完成时间的日期范围。保留开始时间，不覆盖、重算或改写，也不得用普通文字追加完成时间。
2. 仅修改同一页面的标题，将状态词“未完成”替换为“已完成”，保持标题其他文字、顺序和格式不变。标题没有“未完成”时不得猜测其他状态词或自行重命名。
3. 任何必需内容或完成时间未成功写入时，不得把标题改为“已完成”。修改后回读页面，确认 ID 未变且标题只发生预期替换。
4. 用户已提供下一步计划时，只做必要的简洁改写并写入指定位置，不扩展新的任务；未提供时在交付时提醒用户补充，不阻塞其他已完成部分。

### 4. 实验报告完成检查

- 实际修改的页面 ID 与用户指定目标一致，且没有改动其他报告。
- 写入前，开始时间、实验原因和实验内容均已由用户填写。
- 实验内容只包含实验事实、关键设置和直接结果；实验结论均有材料支持。
- 图片和生成图表均已上传；数据表使用 FlowUs 原生表格；公式使用原生接口。
- 已通过原生日期属性补充完成时间，并保留原开始时间。
- 标题中的“未完成”已替换为“已完成”，其余内容未改变。
- 下一步计划只包含用户提供的内容；未提供时已提醒用户。
- 已按共同规范完成媒体、公式和最终回读检查。
