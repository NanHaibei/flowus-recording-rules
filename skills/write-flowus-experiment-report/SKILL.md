# Write FlowUs Experiment Report

只完善用户明确指定的一份 FlowUs 实验报告。将用户已经填写或提供的实验事实整理为简洁的“实验内容”和“实验结论”，不要替用户决定实验目的或下一步工作。

## 连接 FlowUs

- 当前环境支持 Agent Skills 时，优先使用 FlowUs 官方 `$flowus-cli` Skill；仅支持 MCP 时使用 FlowUs MCP。
- 第一次连接、认证失败或不清楚接口能力时，完整阅读 [FlowUs 连接与原生功能](references/flowus-skill.md)。
- 先验证 FlowUs 身份、工作区和写入权限。无法可靠写入时，只能提供草稿并明确说明尚未完成，不能声称已更新报告。
- 使用所选 FlowUs 工具的实际说明确定命令和参数，不要猜测不存在的接口。

## 严格限定修改范围

1. 要求用户用页面链接、页面 ID 或其他唯一标识指定目标实验报告。目标不唯一时，先请用户确认，不要写入。
2. 读取目标报告后记录其不可变页面 ID。后续每次读取、上传、插入、更新和回读都必须限定到该页面或其子块。
3. 不要创建、修改或删除其他报告、页面、数据库记录、模板、属性选项或数据库结构。
4. 只修改完成本次任务所必需的目标字段和内容块。保留目标报告中未被用户要求修改的文字、顺序、格式和附件。

## 写入前检查

开始写报告前，读取目标报告并确认以下三项已经由用户填写：

- 实验开始时间
- 实验原因
- 实验内容

任何一项为空、只有占位文字或不能确定是否由用户填写时，停止写入，列出缺失项并提醒用户先填写。不要代填、猜测或根据上下文补全这些内容。

“用户填写”表示事实来源必须来自用户，且上述三项已出现在目标报告中。Agent 可以在检查通过后精炼“实验内容”的措辞，但不能增加用户未提供的实验步骤、参数、结果或原因。

下一步计划不作为开始写作的前置条件。用户尚未提供时保持为空或保留原文，不要自行制定。

## 编写实验内容

- 以目标报告、实验记录、用户文字说明、附件和实验数据为依据，简要整理实验内容。
- 只记录做了什么、使用了什么关键设置以及得到了什么直接结果。保留理解和复现实验所必需的信息，省略冗长过程和无关细节。
- 不要在“实验内容”中混入实验原因、背景铺垫、结论、评价、下一步计划或未执行的工作。
- 不要把推测写成事实。材料之间冲突或关键信息不清楚时，先向用户说明，暂不覆盖相关内容。

## 编写实验结论

- 根据用户提供的记录、数据、图片和表格概括可以直接支持的结论。
- 使用简洁语言说明主要结果、与预期或对照的差异，以及证据明确显示的限制或异常。
- 不要编造实验结果，不要夸大因果关系，不要补写材料无法支持的解释。
- 没有足够证据形成结论时，明确指出证据不足并请用户补充，不要用常识生成结论。

## 使用 FlowUs 原生内容

### 图片和图表

- 用户提供的实验结果图片必须先成为本地文件，再通过 FlowUs 文件上传接口上传，最后以 FlowUs 图片块插入目标报告。
- 不得使用第三方图片 URL、远程图片地址或其他外链作为图片本体。
- 可以根据用户提供的实验数据生成简洁图表。先生成本地图像文件，再上传并插入目标报告；图表不得包含推测或伪造的数据。
- 将图片或图表放在对应实验内容或结论附近，并添加简短说明。
- 如果工具无法上传图片，不要降级为外链；明确报告该部分尚未完成。

### 表格

- 必须使用 FlowUs 原生表格功能创建或更新表格，不要用 Markdown 表格、制表符文本、代码块或图片模拟表格。
- 只录入与当前实验直接相关的列和数据，保持表格简洁。
- 写入后回读表格，确认表头、行列和数值没有错位。

### 公式

- 必须使用 FlowUs 原生公式块或公式富文本接口，不要把 LaTeX 源码写成普通文本、Markdown、行内代码或代码块。
- 公式接口要求的表达式只能作为结构化公式载荷传入，不能作为可见的普通文本降级写入。
- 当前工具不支持 FlowUs 原生公式时，明确报告公式尚未写入，不要声称已完成。

## 补写完成时间

所有正文和媒体写入成功后：

1. 回读并确认“实验内容”和“实验结论”已正确保存。
2. 调用 FlowUs 的原生【日期】功能，在用户填写的实验开始时间后补上实际完成时间；优先将原日期设置为包含开始与完成时间的日期范围。
3. 保留用户填写的开始时间，不要覆盖、重算或改写。
4. 不要把完成时间作为普通文字、Markdown 或代码文本追加。
5. 日期接口不可用或更新失败时，明确说明报告尚未完整完成，不要用文本时间替代。

## 标记报告已完成

正文、媒体、表格、公式和完成时间全部写入并回读成功后：

1. 只读取并修改同一目标报告的标题。
2. 将标题中的状态词“未完成”替换为“已完成”，保留标题的其他文字、顺序和格式不变。
3. 不要修改正文或其他报告中出现的“未完成”，也不要批量修改标题。
4. 目标标题不包含“未完成”时，不要猜测其他状态词或自行重命名；明确报告标题状态未更新。
5. 任何必需内容或完成时间尚未成功写入时，不得把标题改为“已完成”。
6. 修改后回读目标页面，确认页面 ID 未变且标题仅发生预期的状态词替换。

## 处理下一步计划

- 用户已经提供下一步计划时，只做必要的简洁改写并写入目标报告的“下一步计划”位置，不要扩展新的任务。
- 用户尚未提供时，在报告其余部分完成后提醒用户补充；不要阻塞已完成部分，也不要代拟计划。
- 用户之后直接告诉 Agent 下一步计划时，重新确认同一目标报告，只更新该报告的“下一步计划”内容，并保持简洁。

## 完成前验证

结束前重新读取目标报告并逐项确认：

- 实际修改的页面 ID 与用户指定的目标一致
- 没有写入或修改任何其他报告
- 开始时间、实验原因和实验内容在开始写入前均已由用户填写
- 实验内容只包含实验事实、关键设置和直接结果
- 实验结论有用户材料或实验数据支持
- 图片和生成图表均已上传到 FlowUs，不存在外链图片
- 表格使用 FlowUs 原生表格功能
- 公式使用 FlowUs 原生公式接口，不存在可见的 LaTeX 源码
- 完成时间已通过 FlowUs【日期】功能添加在开始时间之后
- 目标报告标题中的“未完成”已替换为“已完成”，标题其余部分未改变
- 下一步计划只包含用户提供的内容；未提供时已提醒用户

向用户返回目标报告链接或页面 ID、完成的修改摘要，以及任何未完成项。
